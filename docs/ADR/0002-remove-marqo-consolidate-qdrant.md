# Remove Marqo, consolidate on Qdrant, generic vector-DB naming

Context: Marqo was the original DEV-index vector store; Qdrant was added later for PROD and, more recently, became the default for DEV too (`VECTOR_BACKEND` defaulted to `qdrant`; no compose file shipped a Marqo container anymore; Marqo was reachable only via the undocumented `VECTOR_BACKEND=marqo` escape hatch). The `VectorStore` protocol (`pipeline/vector_store/`) existed to make Marqo/Qdrant interchangeable, but PROD promotion never went through it — it always hardcoded Qdrant. Marqo had become dead weight: an unused runtime dependency and ~300+ references (routes, a DB column, env vars, docstrings, scripts, docs) carrying its name for something that was functionally all-Qdrant already. Existing deployments have real data in Qdrant and SQLite that must not require reingestion.

Decision:
- Delete the Marqo implementation outright (`pipeline/vector_store/marqo_store.py`, the `VECTOR_BACKEND` selector, the Marqo fallback branch in `ingest_to_vector_db`, raw `import marqo` fallbacks in admin/provenance endpoints, the 7 Marqo-only ops scripts, the `marqo` pip dependency) rather than leaving it behind a runtime toggle. Rollback is `git revert`, not a config flip — this repo already had `VECTOR_BACKEND=marqo` as a "just in case" lever that nobody exercised in over a version of drift, and keeping dead code alive as a hedge has its own cost (it's what caused the naming debt this ADR is cleaning up).
- Rename Qdrant-specific identifiers to generic ones with no DB name baked in: `QDRANT_URL`/`QDRANT_API_KEY`/`QDRANT_COLLECTION_NAME`/`QDRANT_TIMEOUT_SECONDS` (and their `PROD_`/`PROD_SCHEME_` prefixed variants) become `VECTOR_DB_*`; the SQLite column `document_index_status.marqo_doc_id` becomes `doc_id`; `/marqo/search` and `/marqo/indexes/*` become `/search` and `/indexes/*`.
- The `doc_id` column migration is additive-then-cleanup, not a hard cutover: add the column, backfill it once from the old column, write only the new column going forward. The old column is left in place (stale, unwritten) until an operator manually runs `scripts/drop_legacy_marqo_columns.py` once the new code has proven stable. Chosen over dual-writing both columns going forward: the column's value never differed between "Marqo" and "Qdrant" runs (both stored the same document id), so there's nothing to keep dual-writing once the migration is confirmed correct — dual-write would just be code to remove later, for the same win, one release sooner.
- Kept the `VectorStore` protocol abstraction (`pipeline/vector_store/base.py`) even though `QdrantVectorStore` is now its only implementation, rather than collapsing call sites to use `QdrantVectorStore` directly. The protocol is a real seam for tests (fakes without a live Qdrant) and for a future backend change, and every call site already goes through `get_vector_store()` — collapsing it would touch the same surface area for no behavioral gain.
- Env var rename is a clean break, not a dual-read of old+new names — documented in `ENV.md`, no code path falls back to `QDRANT_URL` etc.

Alternatives considered:
- **Keep `VECTOR_BACKEND=marqo` as a permanent rollback lever.** Rejected: it's exactly the kind of "just in case" runtime toggle that let Marqo linger long after it stopped being the default, and it doubles the paths every future change to ingestion/search has to reason about for a rollback nobody has needed.
- **Dual-write `doc_id` and `marqo_doc_id` during a transition window.** Rejected: the two columns hold identical values (the document id), so there was never a scenario where one had data the other lacked — dual-write only pays off when new writes might not be safely readable by old code, which isn't the case here.
- **Rename the `VectorStore` protocol's Marqo-flavored vocabulary** (`search_mode="TENSOR"`, `hybrid_alpha`, `ef_search`, `use_e5_prefix`, `supports_prefixed_tensor_field`). Rejected as out of scope: these are Marqo-*flavored* names, not Marqo *references* (no DB name in the identifier), and changing them is an API redesign, not a "remove references to MarqoDB" cleanup.
